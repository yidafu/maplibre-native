fix(harmony): Fix HTTP response callback not being invoked

Critical fix for black screen issue caused by HTTP response callbacks
never being triggered after CURL requests completed.

Problem:
- CURL requests were completing successfully (running_handles: 1→0)
- However, processCURLMessages() in curl_event_loop.cpp was not calling
  HTTPRequest::handleResult() to process the response
- This caused response data to never be processed and callbacks never fired
- Map remained black screen as tiles were never loaded

Root Cause:
The processCURLMessages() function had a misleading comment saying
"no need to manually call handleResult" but actually did nothing with
the completed request data.

Solution:
1. Added external C function handleHTTPRequestResult() as a bridge between
   CURLEventLoop and HTTPRequest::handleResult()
2. Modified processCURLMessages() to call this bridge function when CURL
   messages indicate request completion
3. Added comprehensive logging at INFO level to track message processing

Changes:
- platform/harmony/maplibre_harmony/src/main/cpp/curl_event_loop.cpp
  * Declare extern handleHTTPRequestResult function
  * Call handleHTTPRequestResult() in processCURLMessages()
  * Add detailed logging for CURL message processing

- platform/harmony/maplibre_harmony/src/main/cpp/http_file_source_harmony.cpp
  * Implement handleHTTPRequestResult() bridge function
  * Cast void* to HTTPRequest* and invoke handleResult()

Testing:
After this fix, logs should show:
- "🔔 Message from CURL: msg_type=1"
- "CURL request COMPLETED!"
- "handleResult called successfully"
- HTTP 200 responses processed correctly
- Map tiles loaded and displayed

This resolves the fundamental cause of the black screen issue in
HarmonyOS MapLibre implementation.
